# Final audit resolution

Date: 2026-09-23. This record resolves the findings in `FINAL_AUDIT.md` against the current TypedRank working tree. No package was published and no live provider or model-weight inference was run.

## Blocker and high findings

- **B01 — resolved.** The root cause was a whole-request character estimate that could not detect Laya's separate instruction, option, and state truncation. `backends/systemone.py` now puts pointwise candidate content in state. `backends/laya_context.py` checks the selected Laya 0.3.7 checkpoint tokenizer, option cap, head budget, and remaining state room before local inference. `LayaBackend` defaults to this strict guard. `LayaHTTPBackend` defaults to strict validation with a required deployment validator. Explicit `allow_provider_truncation` marks returned stages approximate with an unverified-context warning. Regressions: `test_strict_local_context_uses_loaded_checkpoint_components`, `test_http_strict_requires_deployment_context_validator`, `test_http_strict_calls_deployment_validator`, `test_http_truncation_opt_in_marks_result_approximate`, and pointwise wire-state assertions. These are component-level tests with a tokenizer double; actual checkpoint-weight boundary inference remains an opt-in live test.
- **H01 — resolved.** Laya 0.3.7's shared Router is not certified for concurrent inference. `LayaBackend.__post_init__` rejects `max_inference_concurrency > 1`; the worker remains serialized. Regression: `test_local_model_validation` and `test_local_worker_does_not_block_loop_and_serializes_by_default`.
- **H02 — resolved.** Cancellation previously interrupted shutdown after setting the closed flag, preventing a later unload. `LayaBackend.aclose` now shields one retained cleanup task that drains the executor and unloads the Router; queued calls recheck the closed flag. Regression: `test_cancelled_close_still_unloads_router`.
- **H03 — resolved.** Cancellation previously released the embedding lock while its thread continued. `SentenceTransformerBackend` now retains tracked worker tasks under the async lock, shields them from caller cancellation, and drains them before closing. Regressions: `test_cancelled_embedding_retains_serialization_and_close_drains` and `test_embedding_close_waits_for_inflight_worker`.
- **H04 — resolved.** HTTP auto routing could return different checkpoints across pointwise batches. Laya HTTP now requires a recognized routed checkpoint in auto responses, and the executor rejects a stage whose responses resolve to multiple checkpoints rather than merging those scores. Regressions: `test_http_auto_requires_resolved_checkpoint` and `test_http_auto_rejects_mixed_resolved_checkpoints`.
- **H05 — resolved.** The local preparation hook previously saw only the query. It now receives projected survivor texts. Auto routing checks each survivor with Laya's Router; a multilingual survivor selects the multilingual checkpoint unless the caller explicitly supplied a language or model. Regressions: `test_local_stage_pins_multilingual_checkpoint_and_provenance` and `test_auto_route_checks_multilingual_survivor_separately`. A no-weight Laya 0.3.7 Router smoke check also routed a Hindi survivor to `multilingual`.
- **H06 — resolved.** Network denial previously excluded only declared remote backends. Both explicit execution and `BackendRouter` now require an explicit local declaration under deny/offline; unknown locality is excluded. Regression: `test_unknown_location_is_rejected_under_network_denial` and existing remote-policy tests. This trusts backend declarations; it is not an OS network sandbox.

## Medium findings

- **M01 — diagnostics fixed; inheritance retained.** Jev-specific timeout and reasoning errors could surface for Laya HTTP. Provider hooks now give Laya HTTP its own timeout message and stage, and Laya reasoning validation is explicit. Regressions: `test_http_timeout_has_laya_diagnostic` and `test_laya_http_reasoning_diagnostic_is_provider_specific`. A complete extraction of common HTTP request/transport ownership from `JevBackend` remains future refactoring because it would add a larger hierarchy without changing the verified runtime behavior.
- **M02 — generic cost coupling fixed; compatibility API retained.** `_runtime/executor.py` now calls only the backend's documented `estimated_cost` hook and no longer reads Jev tariff fields. Regression: `test_generic_executor_ignores_legacy_jev_tariff_fields`. The explicit `Reranker(backend=backend)` API remains the recommended path. The legacy `typesafe:` string constructor and its synchronous ownership behavior remain for compatibility; arbitrary caller-owned model backends still require async `rerank`.
- **M03 — resolved.** `FakeBackend` had one cache identity for different scoring configurations. Each instance now gets a distinct identity, keeping repeated calls on one instance cacheable without cross-instance contamination. Regression: `test_fake_backend_cache_identity_is_per_configuration`.
- **M04 — resolved for model stages.** Missing coverage was inferred after top-k slicing. `RankingOutcome.missing_count` now carries validated missing IDs through listwise, pointwise, and pipeline model stages; the facade reports scored and missing counts from that value and sets partial status directly. Regression: `test_partial_coverage_precedes_top_k_selection`.
- **M05 — resolved.** Per-call timeouts were treated as exhausted total deadlines and context limits bypassed router fallback. A model-call timeout now raises retryable `BackendError`; router fallback also accepts `ContextLimitError`. Total request deadlines and cancellation still stop execution. Regressions: `test_backend_timeout_can_fall_back` and `test_context_incompatibility_can_fall_back`.
- **M06 — resolved.** Auto planning filtered router choices for pointwise before testing listwise. It now considers the mode appropriate to the candidate pool and can choose a pointwise fallback when a listwise-only primary does not fit. Regressions: `test_auto_router_selects_listwise_only_backend` and `test_auto_uses_pointwise_fallback_when_listwise_primary_cannot_fit`.
- **M07 — resolved.** Generic custom-backend accounting was not checked before budget reconciliation. The executor now rejects invalid attempts, latency, token counts, and cost, including attempts beyond the reserved maximum, before reconciliation. Regression: `test_invalid_backend_accounting_is_rejected` (five invalid forms).
- **M08 — dependency bound fixed; live certification limited.** The Laya extra is pinned to `laya==0.3.7` in `pyproject.toml` and `uv.lock`. Clean Python 3.11 installations of the Laya and all extras succeeded, and Laya's Router imported and routed without model weights. Actual GPU/CPU inference, checkpoint loading/eviction, and other Python/OS combinations were not run; the opt-in live test remains skipped.
- **M09 — labels corrected; warm/device measurements still unavailable.** The benchmark now names requested settings `configured_device` and `configured_max_batch_size`, and names case timings `first_case_latency_ms` and `later_case_median_latency_ms`. `cold_start_ms` and `warm_latency_ms` stay null because heterogeneous cases cannot establish isolated load or comparable warm inference. The local synthetic smoke report at `benchmarks/audit-smoke.json` contains only measurements actually run by this project. Observed device and actual batch-size telemetry remain future benchmark work.
- **L01 — unchanged.** The low-severity listwise `SMALLER_BATCHES` option remains ineffective for an oversized single group; no uncalibrated listwise chunk merge was introduced.

## Release checks actually run

- `pytest --cov=typedrank --cov-report=term -q`: **187 passed, 3 skipped; 89% statement coverage**. Skips are the opt-in billable Jev request, running Laya HTTP service, and local Laya weight download/inference.
- `ruff check .` and `ruff format --check .`: passed.
- `mypy src/typedrank benchmarks/compare.py`: passed, 42 source files.
- `python -m build`: produced sdist and wheel. Wheel inspection confirmed `typedrank/py.typed`, the new context guard, and no `jev_rankkit` package.
- `uv lock --check`: passed.
- The **final rebuilt wheel** was installed into five separate clean Python 3.11 virtual environments: base, `[jev]`, `[laya]`, `[embeddings]`, and `[all]`. All five import/behavior smoke checks passed. The base and Jev import checks loaded neither Torch nor Laya. A Laya mock inference succeeded with `TYPESAFE_API_KEY` unset, followed by a real Laya Router import/routing check. Laya HTTP mock scoring worked in the Jev-only environment, which contains neither local Laya nor Torch. The embeddings extra imported Sentence Transformers; `[all]` resolved Laya 0.3.7, Sentence Transformers 6.1.0, and httpx 0.28.1.

The smoke environments verify installation, imports, and lightweight behavior, not live quality, GPU safety, API cost, or model latency. Nothing was published.
